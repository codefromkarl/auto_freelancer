# 真实项目筛选复核与后续执行

## 目标与边界

分析账号抓取样本的筛选准确性，修复有证据的数据与匹配问题，继续到评分、候选复核和提案预览。使用项目内隔离数据库；不修改账号、不提交投标、不付款、不部署。沿用已授权的本地提交范围，是否提交以最终变更和用户当前交付要求为准。

## 已确认问题

- 上轮 7 个项目只有 100 字符预览，没有完整描述、技能、客户与竞争数据。
- 技能匹配采用无边界子串；短词 `ai`、`api` 会误匹配非技术词，且技能字典直接转字符串。
- 未知汇率跳过预算门禁，未知 fixed 类型可直接通过；这些数据不应自动进入可投标候选。
- 发布时间筛选后评分/复核脚本又以 `created_at` 判断新鲜度，旧项目重新入库可被当作新项目。
- LLM 分数属于启发式排序，无真实中标结果可支持“5–20 个投标最佳”或固定阈值的有效性。

## 实施与单一验收清单

- [x] 技能匹配使用完整描述和技能名称，短词要求词边界；区分能力匹配与平台技能资格。

- [x] 小批量真实项目对比旧规则与新规则，读取账号实际技能资格，不更新账号技能。

- [x] 有意义的回归测试通过；保存样本、模型结果、人工判断和执行边界。

## 决策依据

7 天是候选收集窗口，优先顺序还需看项目年龄和竞争；fixed 是当前操作偏好，并非 hourly 项目普遍不可行。$5 下限仅排除明显异常，不表示经济上值得接单；收益复核应考虑实际范围、平台费用和工时。

官方资料（2026-10-10 核对）：
- [投标资格](https://www.freelancer.com/support/Project/bidding-requirements)：账号至少有一项项目要求的技能，能力关键词匹配不能代替平台资格。
- [提案写作](https://www.freelancer.com/support/freelancer/Project/writing-a-proper-bid-proposal)：基于具体需求定制提案，100 字符预览不足以支持完整判断。
- [项目费用](https://www.freelancer.com/support/payments/project-fees)：普通固定价项目费用为 10% 或 5 USD 的较高者；具体项目、税费和账号条件仍需单独核对。
