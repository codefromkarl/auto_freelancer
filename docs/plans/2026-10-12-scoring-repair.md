# 投标筛选与评分修复

## 范围与边界

执行本轮筛选审计确认的问题修复，沿用现有 Python 服务及流水线。以当前未提交工作区为基线，在项目内隔离工作区实现并验证，保留无关修改。不提交 Git、不调用付费模型、不发送通知、不投标、不执行业务库迁移或部署。

## 决策与契约

- Web 与 CLI 使用同一 LLM 评分服务；模型给出可验证的维度及工时，程序计算经济性、竞争分与加权总分。取消重复新人加分，缺少结构化维度或有效工时不得用关键词估算补成可投候选。
- 使用实际美元建议报价、普通 fixed 费用估算净时薪；不把低时薪抬至下限。缺失数据明确保留未知。
- 保存来源、评分版本、输入摘要、策略/模型信息、维度、经济计算及评分时间。旧版及手动评分可展示，但不自动进入本轮候选；需按新契约重评。
- 竞争、客户、技能和发布时间变化清除旧评分；年龄通过可配置 TTL 重评。缓存包含完整载荷、模型及策略。
- 已知硬条件检查先于数量截断。准备阶段发生失败后补选，重复被拒候选跳过；人工审批及真实提交开关继续有效。
- 初筛增加开发交付语义，避免普通视频剪辑、媒体设计和 AI 写作凭泛词进入能力匹配。
- 规则评分仅用于明确标记的本地参考分析；词边界及小任务判断修复，不再覆盖 Web 正式评分。
- 新增评分元数据列的兼容迁移仅在隔离数据库验证；未运行实际业务库初始化。
