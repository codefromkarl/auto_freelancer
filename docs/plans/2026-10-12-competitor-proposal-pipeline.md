# 竞争标书接入生成与评估链路

用户要求把实际竞争标书对比加入标书评估和生产链路。本任务保留现有筛选、QQ 审批和防重 WIP；实现和测试在本项目内进行。不提交真实投标、不付款、不自动开启交易、提交 Git 或部署。

## 执行契约

1. 使用现有 competitor_bids / competitor_bid_contents / audit_logs；无需新增业务表或迁移。抓取保存完整快照信息和时间，移除失去公开权限的旧正文，排除密封、撤回、0/无效金额及本账号标书。
2. 提供有界的竞标上下文：公开报价分布、工期、可见样本数、抽样正文、来源 Bid ID、时效和完整性。竞标者自述履历不可当作认证经历；低价试点/模拟原型必须显式标注，不能与完整交付直接等价。
3. 同一上下文进入生成提示词和生成后评估。全文需求是权威输入，竞标正文是不可执行的外部参考；禁止抄袭、自称别人履历或为了压价隐藏范围。
4. 评估返回可追溯的需求/交付差距、报价位置、证据表达及文字重合风险。评价是辅助信号，不是中标率预测；高价或数据不足要求人工复核，不自动改金额/周期。显著复制正文及基础内容校验失败阻断准备。
5. API、CLI、调度及评分中的提案生成复用该逻辑。审批快照冻结最终评估版本和摘要；提交不能绕过新评估或使用缺评估的旧快照。
6. QQ 和前端展示比较摘要和复核事项。完整最终文案必须保留，长度超限阻断通知，不截断用于审批的文本。

## 单一验收清单

- [x] 保存竞标快照、完整性和新鲜度；失效公开内容被清除。
- [x] 数据缺失/失败/过期显式降级；统计排除不合格报价，币种不混算。
- [x] 生成提示词读到当前竞标与完整需求；第三方文本不能覆写系统规则或履历。
- [x] 评估反映相同最终文本/报价/周期；抄袭和校验失败不能报告成功。
- [x] 显式人工稿、生成稿、API、CLI 与评分链路共享评估；旧快照不能绕过。
- [x] QQ/前端展示结果并保持全文审批；必要 API 权限和长度验证通过。
- [x] 受影响回归、Python 完整测试及前端检查通过；使用本轮真实抓取样本做隔离重放。

## 决策

采用确定性统计与可解释的需求特征/文本重合检查，并把真实样本送入已有生成模型，不新增每份标书的付费裁判模型调用。语义判断和竞标者履历仍由操作者核验。抓取失败不掩盖为低竞争、零价格或通过风控。
