BidMaster Local

How this preview handles data

This page describes the implemented local preview. It is not a claim that a public paid service, merchant account or legal entity has been launched.

On your device

Profiles, imported briefs, assessments, proposals, task history and submission receipts are stored in your OS user-data directory. Model API keys and platform tokens use the OS credential vault. A transient local session key authorizes the browser interface; it is not a model credential.

Requests you choose

Model tasks send the necessary brief and user background directly to the HTTPS endpoint you configure. That provider's processing and retention policies apply. Platform requests require separate permission and account authorization. These requests are not relayed through publisher infrastructure.

Diagnostics and telemetry

No product analytics or automatic log upload is enabled. User-exported safe diagnostics exclude keys, profile/project contents, prompts and raw logs. Share only diagnostics you have reviewed.

Software access

Signed license documents include an installation identifier, capabilities and validity period. The current preview verifies them locally. Hosted checkout and automated merchant activation are not active. Any future cloud order service needs its own disclosed data handling and commercial terms before launch.

Removal and backups

You can remove saved keys in the app. Uninstall preserves working data so an upgrade or accidental uninstall does not erase receipts. You can remove the separate data directory yourself after exporting records and reconciling outstanding or unknown submissions. Do not overwrite a newer submission ledger with an old backup.
